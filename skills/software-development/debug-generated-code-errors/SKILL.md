# Debugging and Fixing Generated Code Errors

When generated code (like HTML, JavaScript, CSS from a template or script) exhibits syntax errors or unexpected tokens, the root cause often lies in the *generating script* rather than a direct error in the output file itself. This skill outlines a process to trace and fix such issues.

## Symptoms

- `Uncaught SyntaxError: Unexpected token 'X'`
- `Uncaught ReferenceError: Y is not defined` (when the definition *should* be present in the generated code)
- Literal template placeholders (e.g., `***`, `{{}}`) appearing in the final output.

## Diagnosis Steps

1.  **Identify the exact error in the generated output:** Note the line number and the problematic token(s) from browser console or build logs.
2.  **Locate the generator:** Determine which script or template is responsible for producing the problematic section. Use `grep` on the codebase for parts of the generated code to find its source.
3.  **Inspect the generator's source:**
    *   Use `read_file` to view the generator script (e.g., Python, Jinja2 template).
    *   Focus on the section of the generator that corresponds to the erroneous output line.
    *   Be aware of **string literal nuances**:
        *   Python f-strings or `.format()` methods might require double curly braces `{{}}` to output single curly braces `{}` in the final string.
        *   Placeholders like `***` might be literal strings that were not correctly replaced or intended dynamic content that failed to render.
    *   Compare the *Python/template syntax* with the *expected generated output syntax*.

## Fixing Strategy (Robust Programmatic Approach)

Direct `patch` calls can be brittle if the `old_string` does not perfectly match due to hidden characters, encoding, or dynamic generation. A more robust approach uses `execute_code` with Python's string manipulation or regular expressions.

1.  **Read the entire generating script:**
    ```python
    from hermes_tools import read_file, write_file
    file_path = '/path/to/generating_script.py'
    file_content_result = read_file(file_path)
    if file_content_result.get('error'):
        print(f"Error reading file: {file_content_result['error']}")
        return # or handle error
    file_content = file_content_result['content']
    ```

2.  **Identify the precise `old_string` in the generator:**
    *   If a direct regex search for `problematic_js_fragment` in the *Python raw file content* doesn't work, manually inspect using `read_file` with `offset`/`limit` around the suspected line.
    *   If necessary, extract lines and print their `repr()` to reveal any non-printable characters or exact Python string literal forms (e.g., `print(repr(line))`).
    *   The `old_string` needs to match the *Python literal* that produces the incorrect JavaScript. For example, if the JavaScript `const author_data=*** || {};` is generated by a Python line like:
        `js_code_snippet = "            const author_data=*** || {{}};"`
        Then `old_string` should be `"            const author_data=*** || {{}};"` (the Python string literal).

3.  **Perform the replacement:** Use `str.replace()` or `re.sub()` within `execute_code`. `re.sub()` is preferred for flexibility against minor whitespace variations.

    ```python
    # Example using str.replace() (if exact match of Python literal is found)
    old_python_string_literal = "            const author_data=*** || {{}};" # Exact string from Python source
    new_python_string_literal = "            const author_data = tweet.author || {};" # Corrected Python string literal for desired JS

    updated_content = file_content.replace(old_python_string_literal, new_python_string_literal)

    if updated_content == file_content:
        print("Error: Old string not found or content did not change. Verify 'old_python_string_literal'.")
    else:
        write_file(file_path, updated_content)
        print("Successfully updated the generating script.")
    ```
    ```python
    # Example using re.sub() (more robust against minor variations)
    import re
    old_python_regex_pattern = r"(\s*)const author_data=\*\*\* \|\| \{\{\}\};"
    new_python_literal_for_js = r"\1const author_data = tweet.author || {};" # Use \1 to preserve original indentation
    updated_content = re.sub(old_python_regex_pattern, new_python_literal_for_js, file_content)

    # ... (check and write file as above)
    ```

4.  **Re-run the generating script:** After modifying the generator, it must be executed to produce the corrected output file.

    ```python
    terminal_run_result = terminal(command="python3 /path/to/generating_script.py")
    if terminal_run_result['exit_code'] == 0:
        print("Generated file successfully updated. Please check the output.")
    else:
        print(f"Error regenerating file: {terminal_run_result['output']}")
    ```

## Pitfalls

-   **`old_string` mismatch:** The most common failure. Always get the exact Python `repr()` of the problematic line from the file if simple string matching fails.
-   **Invisible characters:** Line endings (`\r\n` vs `\n`), unexpected spaces, or zero-width characters can break matches. `repr()` helps expose these.
-   **Dynamic content:** Ensure you're replacing the *template* code, not just one instance of the generated text, so future generations are also correct.
