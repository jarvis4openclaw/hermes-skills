# wahid.md — agent-facing personal page

A single-page identity artefact modelled on lauren.md: **`index.md` is canonical**, `index.html` is the human rendering of the same source. The whole point is that a crawler or LLM fetcher gets clean Markdown; a browser gets the styled page.

## When to Use

- Editing `index.md` / `index.html` for wahid.md
- Deploying or redeploying the site, or checking what is actually live
- A crawler, agent, or browser reports the wrong thing at `https://wahid.md`
- Attaching or debugging the custom domain / TLS / redirects

## Not For

- Verifying that an unrelated static-site push is live → use `static-site-deploy-verify` instead.
- SSH/SFTP file transfers → use `ssh-file-deploy` instead.
- A general web-quality/accessibility audit of the page → use `web-quality-audit` instead.
- Authoring content for a different site (this skill owns only `~/clawd/wahid-md/`).
- Standing up a brand-new Cloudflare Worker/Pages project → scaffold it first, then return here for the `.md` negotiation contract.

## Layout

```
~/clawd/wahid-md/
  index.md            canonical source (agent-facing)
  index.html          human rendering — keep in sync by hand
  scripts/build.sh    stages public/ = {index.html, index.md} ONLY
  worker/index.js     content negotiation, redirects, robots.txt, llms.txt
  wrangler.toml       Worker + static assets + custom domains
  public/             generated; gitignored
  *.bak-YYYYMMDD-*    local drafts; gitignored — never publish these
```

## Deploy

```sh
cd ~/clawd/wahid-md
./scripts/build.sh
CI=1 npx --yes wrangler@4 deploy      # OAuth as wahidmy@proton.me, account 239c7bfe...
```

Live: `https://wahid.md` and `https://www.wahid.md` (custom domains on the `wahid-md` Worker). No Pages project — Workers static assets, because Pages cannot do `Accept`-based negotiation.

## Behaviour contract (verified)

| Request | Result |
|---|---|
| `GET /` `Accept: text/html` | 200 `text/html` — index.html |
| `GET /` `Accept: text/markdown` | 200 `text/markdown` — index.md |
| `GET /` no/other Accept | 200 `text/markdown` — index.md (default) |
| `/index.md`, `/llms.txt` | 200 `text/markdown` |
| `/robots.txt` | 200 `text/plain`, allow-all, `Content-Signal`, `Sitemap:` directive |
| `/sitemap.xml` | 200 `application/xml`, generated by `build.sh` |
| `/index.html` | 302 → `/` |
| `http://` | 301 → `https://` |
| `www.` | 301 → apex |
| anything else | 404 (drafts, config, worker source must never resolve) |

All responses carry `Vary: Accept`, `cache-control: public, max-age=300`, HSTS, `nosniff`, and a `script-src 'none'` CSP. Keep the cache short: an hour-long TTL on the negotiated HTML serves a stale policy after a header change (measured: pre-CSP HTML kept loading the beacon).

## Release tagging

The site lives inside the `clawd` repo, which already has an upstream, so releases are tagged **locally with a namespaced name** and never pushed:

```sh
git add wahid-md/index.html wahid-md/.gitignore wahid-md/scripts wahid-md/worker wahid-md/wrangler.toml
git commit -m "wahid.md vX.Y.Z — …"
git tag -a wahid-md-vX.Y.Z -m "…"     # no `git push --tags`
```

Do not `git init` inside `wahid-md/`: the parent repo tracks its files and an embedded repo breaks the nightly auto-sync.

## Pitfalls

1. **Editing only `index.md` or only `index.html`** — there is no generator, so the two drift silently and the Markdown (what agents read) stops matching the page. Edit both together.
2. **Editing without a backup** — always `cp -p index.html index.html.bak-$(date +%Y%m%d-%H%M%S)`, then run `./scripts/build.sh` so `public/` matches.
3. **`assets.directory` not pointed at `./public`** — pointing it at the project root publishes 30+ drafts. Keep `assets.directory = "./public"`.
4. **`html_handling` not set to `"none"`** — the Worker's own `/index.html` fetch 307-redirects into itself and browsers loop. Keep `html_handling = "none"`.
5. **A non-root path that resolves instead of 404** — unknown paths reach the Worker by design; every non-root path must 404 explicitly (drafts, config and worker source must never resolve).
6. **Declaring success without verifying** — re-run the behaviour matrix, including `curl` for a `.bak` path and a `Python-urllib` UA: the zone's bot rules can answer `error code: 1010` (403) to agent clients.
7. **Zone-level extras left on** — email obfuscation and bot rules must stay off (they broke `Python-urllib` until Browser Integrity Check was disabled). The zone still injects a Web Analytics beacon into HTML; the CSP is what makes it inert — diff served vs staged HTML, the beacon is the only expected delta.
8. **Weakening the Content-Signal policy** — keep `ai-train=no, search=yes, ai-input=yes`; the page exists to be read and cited, so `ai-input` must stay on. Measure with the scan, then read `details.signals` to confirm what the parser actually saw.
9. **Testing negotiation from a local `http.server`** — it serves `.md` correctly but does NOT negotiate on `Accept`. Use the deployed URL to test negotiation.
10. **An hour-long cache TTL on the negotiated HTML** — it serves a stale policy after a header change (measured: pre-CSP HTML kept loading the beacon). Keep `max-age=300`.
11. **`git init` inside `wahid-md/`** — the parent `clawd` repo tracks its files; an embedded repo breaks the nightly auto-sync. Tag locally with a namespaced name (`wahid-md-vX.Y.Z`) and never `git push --tags`.
